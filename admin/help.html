Website editing guide

Routine updates do not require coding. Pages CMS edits the content stored in GitHub, and GitHub Pages republishes the public site. These instructions are written so future chapter leadership can inherit the website without knowing how it was originally built.

Article 01

Getting started with the editor

  1. Open Pages CMS and sign in with an authorized account.
  2. Select the repository that contains the chapter website.
  3. Use Website for Site settings, Chapter members, Support & payments, and Custom pages.
  4. Use Chapter content for Events, Student projects, and Jobs & internships.
  5. Save the edit, then verify it on the public website.
Normal editors should not need GitHub. Pages CMS writes the repository changes for you. GitHub is mainly needed for ownership, permissions, history, and structural/code changes.

Article 02

Edit site settings and chapter links

Open Website → Site settings. This controls the chapter name, header name, tagline, homepage introduction, About-page description, public chapter email, Instagram URL, AIAS membership URL, UofM Architecture URL, and announcement banner.

Instagram

Enter the full chapter Instagram URL beginning with https://. The site reuses that link on the homepage, About page, and footer.

Announcement banner

Enter a short message to show it above the site navigation. Clear the field completely to hide it.

Before launch: replace placeholder contact information and remove any prototype/sample announcement.

Article 03

Create and maintain chapter member profiles

Open Website → Chapter members. The member directory is intended for the chapter as a whole, not only formal officers. A member can describe their chapter contribution using any useful public role such as President, Member, Events Committee, Professional Outreach, or another responsibility.

  1. Add a member and create a permanent Member URL name, such as jordan-smith.
  2. Add the member's public name and chapter role/contribution.
  3. Optionally add their program/year and design or professional interests.
  4. Upload a profile photo and write a short accessibility description. If no photo is supplied, the site displays initials.
  5. Write the Short introduction / blurb. This is used on cards and in the quick-view popout.
  6. Optionally write a longer Full profile description. This appears in the popout and full profile page.
  7. Add a public email only when the member wants it published.
  8. Keep Show public member profile enabled for members who should appear publicly.

Member URL names

Treat the member URL name as a permanent identifier after publication. It links the public profile to student projects. Changing it later can break existing profile links and project associations.

What visitors see

The About page previews several members. The Members page lists the full chapter and supports searching. Selecting a member opens a quick-view popout; the full member page contains the longer profile and every linked student project.

Get permission. Do not publish a student's photo, personal email, biography, or school work without their approval.

Article 04

Publish a student project and link it to a member

Each student project has its own public project page with a gallery and full narrative. Projects can also appear automatically on a chapter member's profile.

  1. Open Chapter content → Student projects and add or edit a project.
  2. Enter the Project title, Student name, and a permanent Project URL name.
  3. To associate the project with a public member profile, copy that person's Member URL name from Website → Chapter members into Member profile URL name.
  4. Add studio/course, semester, year, and project type when useful.
  5. Write the short project summary and choose a strong cover image.
  6. Add gallery images in presentation order. Give every gallery image an accessibility description and use captions when useful.
  7. Write the long-form project narrative and optionally add an external portfolio/publication link.
  8. Save and test the project page. If it was linked to a member, open that member's profile and confirm the project appears there.

Example association

If the member's URL name is jordan-smith, enter exactly jordan-smith in the project's Member profile URL name field. The Admin Dashboard flags project links that do not match an existing member.

Fallback behavior: older projects without a member URL can still match a profile when the project's Student name exactly corresponds to a member name, but using the explicit member URL is more reliable.

Article 05

Add or update an event

  1. Open Chapter content → Events.
  2. Give the event a permanent Event URL name.
  3. Add date, time, location, short summary, and optional event image.
  4. Use Full event details for agenda, speakers, parking, what to bring, or other expanded information.
  5. If registration is needed, turn on Show RSVP button and provide the full https:// registration link.
  6. Turn on Feature on homepage when appropriate.
Past events archive automatically. The event date controls whether an event appears as upcoming or past.

Article 06

Post a job, internship, or opportunity

  1. Open Chapter content → Jobs & internships.
  2. Add the position, organization, location, and opportunity type.
  3. Add posted/deadline dates when known.
  4. Write a concise summary rather than copying a full external posting.
  5. Add the original full https:// application link.
  6. Use Show on website to control visibility.

If a valid deadline is present, the public site automatically stops showing the listing after the deadline. The Admin Dashboard still flags expired listings that remain marked active.

Article 07

Manage support and payment buttons

Open Website → Support & payments. The site does not process money itself. It only directs visitors to the chapter's approved third-party payment accounts.

  1. Edit the firm-payment and donation explanatory text as needed.
  2. Under Payment buttons, add the provider, button label, full account URL, and enable the button.
  3. Disable a button to hide it without deleting its saved information.
  4. Keep firm memo/receipt instructions current when they are useful.
Use chapter-controlled accounts only. Verify payment links before publishing them. Do not place card numbers, bank credentials, passwords, private keys, or API secrets in the repository.

Article 08

Create a custom information page

  1. Open Website → Custom pages.
  2. Add a title and permanent lowercase URL name.
  3. Optionally provide a shorter navigation label.
  4. Enable Show in main navigation only when the page deserves a permanent top-level link.
  5. Add an introduction, optional hero image, and formatted content.
Avoid casually changing a URL name after launch. Bookmarks and shared links depend on it.

Article 09

Images and media

Images uploaded through Pages CMS are stored in assets/uploads/ inside the website repository, so they move with the website when repository ownership changes.

  • Use JPG, PNG, or WebP for normal photographs, drawings, and renderings.
  • Compress very large images before uploading.
  • Use portrait-oriented images for member headshots.
  • Landscape images work well for event and project cover cards.
  • Write useful alternative text for meaningful images.
  • Do not upload material the chapter does not have permission to publish.

Article 10

Publishing and verification

Saving in Pages CMS creates a GitHub commit. GitHub Pages republishes the static website from the repository.

  1. Save the CMS entry.
  2. Open or refresh the relevant public page.
  3. Check important edits at desktop and phone widths.
  4. Test newly added external links.
  5. For events, open the expanded event page.
  6. For projects, click through the complete gallery.
  7. For member profiles, test both the quick-view popout and full profile page, including any linked projects.

The repository's commit history preserves previous content versions if a change needs to be investigated or reverted.

Article 11

Editor access and website handoff

Keep long-term ownership with the chapter rather than one student's personal account. A chapter-owned GitHub organization with at least two current organization owners is the preferred production setup.

Officer transitions

  • Add new authorized editors before outgoing officers lose access.
  • Remove access that is no longer needed.
  • Keep at least two people capable of managing repository ownership and Pages CMS authorization.

Repository transfer

The website files, JSON content, images, CMS schema, and Git history all live in the repository. If ownership changes, transfer the repository rather than rebuilding the site. After transfer, verify GitHub Pages and authorize Pages CMS for the repository under its new owner.

Article 12

Troubleshooting common problems

A saved change is not visible

Refresh the public page and confirm the CMS save completed. If necessary, check the repository's GitHub Pages deployment status.

A member does not appear

Confirm the member has a valid Member URL name and Show public member profile is enabled.

A project is missing from a member profile

Compare the project's Member profile URL name with the member's Member URL name. They must match exactly. The Admin Dashboard will flag unknown member links.

A button/link does not appear

External links must use a complete https:// address. Some buttons are intentionally hidden when their URL is blank or the related visibility toggle is off.

Pages CMS shows an error

Hard-refresh the CMS first. If the problem continues, avoid changing the raw configuration and have a site administrator inspect .pages.yml.

Article 13

Privacy, permissions, and content safety

This is a public website backed by a public repository. Treat everything saved through the CMS as public information.

  • Never store passwords, API keys, tokens, banking credentials, private student records, grades, or other secrets.
  • Get student permission before publishing their name, portrait, biography, or project work.
  • Use a chapter-wide contact email when possible instead of personal contact information.
  • Do not publish copyrighted photographs, drawings, firm work, or client material without permission.
  • Verify external payment, job, RSVP, and social links before publication.
