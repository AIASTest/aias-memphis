Website editing guide

Routine updates do not require coding. Use Pages CMS for content, then verify the result on the public site. These articles are designed so a future officer can maintain the site without knowing how it was built.

Article 01

Getting started with the editor

  1. Open Pages CMS and sign in.
  2. Select AIASTest / aias-memphis.
  3. Choose Website for global settings/pages/leadership or Chapter content for events/projects/jobs.
  4. Edit the fields and save.
  5. Open the public site and confirm the change looks correct.
Normal editors should not need GitHub. The CMS writes changes to the repository for you. GitHub is mainly for site structure, code, history, and ownership.

Article 02

Edit site settings and homepage text

Open Website → Site settings. This controls the chapter name, header name, tagline, homepage headline/introduction, About-page description, public email, Instagram URL, membership URL, department URL, and announcement banner.

Announcement banner

Enter a short message to show a banner above the navigation. Clear the field completely to hide it.

External links

Use the complete address beginning with https://. The CMS validates these links before saving.

Launch checklist: replace the placeholder public email and remove the prototype/sample banner before presenting the site as final.

Article 03

Add or update an event

  1. Open Chapter content → Events.
  2. Add a new item or select an existing event.
  3. Enter the event name and date. Add time/location when known.
  4. Write a concise description that makes sense without extra context.
  5. Optionally upload an image and add an accessibility description.
  6. For registration, paste the full https:// RSVP link.
  7. Turn on Feature on homepage for high-priority upcoming events.
  8. Save and preview both the homepage and Events page.
Past events archive automatically. When an event date passes, it moves from Upcoming Events to Past Events. You normally do not need to delete it.

Article 04

Publish a student project portfolio

Each student project has its own public detail page. The project card on the homepage or Student Work page opens that detail page automatically.

  1. Open Chapter content → Student projects and add a new item.
  2. Enter the Project title and Student name.
  3. Create a permanent Project URL name such as river-threshold. Use lowercase letters, numbers, and hyphens only.
  4. Add studio/course, semester, year, and project type when useful.
  5. Write the Short project summary. This appears on the project card and near the top of the project page.
  6. Choose a strong Cover image. This is the image visitors see before opening the project.
  7. Build the Project gallery. Add gallery items in the order they should appear. Each item should have an image, a short accessibility description, and an optional visible caption.
  8. Write the Full project description. This is a rich-text area intended for a real design narrative, not just one paragraph. Headings, paragraphs, lists, emphasis, links, and inserted images are supported.
  9. Optionally add a full https:// link to the student's portfolio, a publication, video, or other external project page.
  10. Use Feature on homepage for work you want highlighted, then save and open the project's public detail page to test the complete gallery.

Gallery order

The first gallery item opens first. Drag/reorder gallery items in the CMS to control the sequence. On the public page visitors can use thumbnails, previous/next buttons, the large image, or the keyboard arrow keys.

Project URL names

Treat the project slug as permanent once a link has been shared. Changing it changes the project's URL and can break old links.

Get permission. Confirm the student agrees to publication of their name and work. Do not publish private critiques, grades, unpublished client material, or other sensitive information.

Article 05

Post a job, internship, or opportunity

  1. Open Chapter content → Jobs & internships.
  2. Add the position title, firm/organization, location, and opportunity type.
  3. Add the posted date and deadline when known.
  4. Summarize the role without copying an entire job posting.
  5. Use the employer's original full https:// application link.
  6. Leave Show on website enabled while the listing is current.

If a valid deadline is entered, the public website automatically stops displaying the listing after that date. The Admin Dashboard will still flag it for cleanup if it remains marked active.

Article 06

Update chapter leadership

Open Website → Leadership. Each entry has a name, position, and optional public email address. Keep the list current when officer terms change.

Email is optional. Leave it blank if the person does not want a personal address published. A chapter-wide email in Site Settings is generally preferable for continuity.

Article 07

Create a custom information page

  1. Open Website → Custom pages and add an item.
  2. Choose a clear title.
  3. Set the URL name (slug), for example scholarships. Use lowercase letters, numbers, and hyphens only.
  4. Optionally provide a shorter navigation label.
  5. Turn Show in main navigation on only for pages that deserve a permanent top-level link.
  6. Add an introduction, optional hero image, and formatted page content.
Avoid casually changing a slug after launch. Existing bookmarks or shared links use that slug and can break if it changes.

Article 08

Images and media

Images uploaded in Pages CMS are stored in assets/uploads/ inside the website repository. They remain with the site when leadership changes.

Recommended practice

  • Use JPG, PNG, or WebP for normal photos, drawings, and renderings.
  • Compress very large files before uploading.
  • Landscape images work best for event and project cover cards.
  • Project gallery images can use different proportions; the detail viewer contains them without cropping.
  • Use short, descriptive alt text for meaningful images.
  • Use captions when a drawing, diagram, model, or process image benefits from explanation.
  • Do not upload copyrighted material unless the chapter has permission to use it.

Article 09

Links and formatted text

External links

Always paste the complete address beginning with https://. Examples include registration forms, employer postings, University pages, project portfolios, and social accounts.

Rich-text editors

Custom-page content and the full student-project narrative use a rich-text editor for headings, lists, emphasis, links, and images while storing the content as Markdown. Rich-text documentation

Broken link behavior

The public site intentionally refuses unsafe or malformed external URLs rather than rendering a questionable link. The Admin Dashboard also flags common bad links.

Article 10

Publishing, verification, and history

When you save in Pages CMS, it writes the content change to GitHub. GitHub Pages then republishes the static website.

  1. Save the CMS entry.
  2. Open or refresh the public page.
  3. Check desktop and mobile-width layouts for important content.
  4. Open external links you just changed.
  5. For student work, open the project's individual page and click through every gallery image.
  6. If necessary, correct the entry and save again.

Each CMS save becomes a Git commit, so the repository retains a history of changes. Pages CMS commit settings

Article 11

Editor access and collaborators

Only approved people should have editing access. GitHub users with repository access can edit through Pages CMS. Pages CMS also supports invited email collaborators for people who need content/media access without normal GitHub repository management.

When an officer leaves

  • Remove or revoke editing access they no longer need.
  • Confirm at least two current leaders retain administrative access.
  • Keep ownership with the chapter rather than depending on one student's personal account long-term.

Article 12

Troubleshooting common problems

A saved change is not visible

Refresh the public page and confirm the CMS save completed. Check the repository's Actions/Pages deployment if the change still does not appear.

A button or link does not appear

Confirm the URL is complete and begins with https://. Invalid external URLs are intentionally hidden.

An event is missing

Check its date. Events with invalid or missing dates are hidden; past events appear in the archive.

A project card opens “Project not found”

Check that the project has a valid, unique Project URL name. Duplicate or changed slugs can break a detail link. The Admin Dashboard flags this automatically.

A project image is missing from the gallery

Open that gallery item in Pages CMS and confirm an image is selected. Each gallery entry should contain an image and accessibility description.

A job disappeared

Check Show on website and the deadline. Listings stop displaying after a valid past deadline.

Pages CMS shows an editor error

Hard-refresh the CMS first. If multiple sections fail, inspect recent changes to .pages.yml or use GitHub history to identify the change.

Start with the Admin Dashboard. Its Site Health section identifies many content-level problems automatically.

Article 13

Officer handoff checklist

  • Confirm the chapter still controls the GitHub repository and Pages CMS access.
  • Add incoming officers before outgoing officers lose access.
  • Remove access that is no longer appropriate.
  • Update Leadership and public contact information.
  • Review old events and inactive or expired jobs.
  • Replace outdated announcement banners.
  • Check student projects for broken galleries or outdated external portfolio links.
  • Check custom pages for stale dates, links, scholarships, or resources.
  • Run the Admin Dashboard Site Health check.
  • Make sure at least one incoming officer understands this Help Center.

Article 14

Content safety and privacy

Everything in the public repository should be treated as public. Never store passwords, access tokens, API keys, private student records, grades, addresses, unpublished sensitive documents, or other secrets in the CMS or repository.
  • Get student permission before publishing identifiable project work.
  • Use a chapter email rather than personal contact details when practical.
  • Verify employer/job links before publishing.
  • Use only images and graphics the chapter has permission to publish.
  • Keep editor access limited to current authorized leadership.
